KMReader 1.0.0 candidate (build 30) starts from the working 0.9.1 code and retains
its Android update identity, signing certificate and account data.

- Single-page comic curls fade as the outgoing sheet moves away. Double-page
  curls keep their opaque front/back faces.
- Single-page mouse taps and drags use the fitted page width and edges, including
  wide Windows windows with black side margins. Pinch cancellation and zoomed
  panning remain supported.
- Local PC/phone documents can be sent to the active Kindle account's cloud
  library and selected devices, with title/author, streaming progress, cancellation
  and explicit accepted/uncertain results. See [import details](../KINDLE_IMPORT.md).
- Dictionaries are filtered during full/incremental synchronization and when
  reopening old catalog caches, including purchased and known legacy dictionaries.
- Initial Kindle catalog processing moves CPU work off the UI isolate, indexes in
  yielding batches and bounds cover requests to reduce Windows UI stalls.
- Models, AI and translation extensions are future work. Existing experimental
  controls are labeled accordingly; Komga server upload is also future work.

The repository's source/runtime boundaries, dependency map, development/testing
guides and preserved release/branch inventory remain in place. Historical Python
Kindle modules that the app uses are retained. No older release, tag, build or
Android key is replaced by this candidate.

This is a release candidate until complete CI/build checks and target-device
acceptance are recorded in [validation](../VALIDATION.md). Synthetic import tests
do not prove real Amazon account authorization/delivery. Existing 0.9.x drafts
stay drafts; no stable release is published automatically.
