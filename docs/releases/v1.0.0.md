# KMReader 1.0 development previews

Stable 1.0 is still in progress. The current public package is
**[candidate 9, build 39](https://github.com/LeValue/KMReader-Porting/releases/tag/v1.0.0-candidate.9)**
for Android and Windows. See [installation](../GETTING_STARTED.md) and the
[porting checklist](../PARITY.md) for requirements and remaining work.

## Candidate 9 — build 39

[Source CI](https://github.com/LeValue/KMReader-Porting/actions/runs/44391792290) and [delivery](https://github.com/LeValue/KMReader-Porting/actions/runs/44395601567) passed.

- Android reads APK certificates with both PackageManager flags. Certificate
  collection and actual signer mismatches have different error messages. The
  installer still checks package, version, source and the exact installed signer.
- Windows waits for the update helper to acknowledge the job and capture the app
  process before it closes. The helper restarts from the installation directory
  and records replacement and restart failures.
- **Open release page** is available when an update is offered. It allows a manual
  upgrade from an older in-app updater that cannot finish.

## Candidate 8 — build 38

[Source CI](https://github.com/LeValue/KMReader-Porting/actions/runs/44320891587) and [delivery](https://github.com/LeValue/KMReader-Porting/actions/runs/44324495987) passed.

- Kindle ebooks already downloaded can receive newer reading positions at
  opening and while the reader is active. The reader uses the record's latest
  modification time when available.
- The reader offers the new position and keeps the current page until you
  confirm. **Settings → Servers → Automatically resume from Kindle** enables
  immediate jumps. Sync uses the matching edition and keeps any unsent local
  progress in the outbox.
- Accepting an incoming position updates the local reading state without sending
  a reading-position write back to Kindle.

## Candidate 7 — build 37

- Komga book/series cover selection, existing artwork restoration and confirmed
  removal of uploaded images; manual cover refresh for volumes and lists.
- Bounded UI upload-progress updates; response-body timeouts cancel underlying
  work, including a real-socket regression.
- Update downloads retain interrupted prefixes and verify Range responses and
  final SHA256. Error messages distinguish network/storage/integrity/installer
  failures without showing private paths or signed URLs. Package hashing runs
  off the UI isolate. Permission retries reuse the downloaded package.
- Includes the preceding lifecycle/polling energy fixes on `main`.

[Source CI](https://github.com/LeValue/KMReader-Porting/actions/runs/44108656435), [delivery](https://github.com/LeValue/KMReader-Porting/actions/runs/44114394009), downloaded packages and the public update feed passed verification.
If an older updater fails, bootstrap once with the direct signed APK over Preview,
without uninstalling. Build 36 and all previous files remain retained.
Physical phone energy measurements and the reported update flow still need
installed-device acceptance. Do not interpret automatic checks as stable parity.

## Candidate 6 — build 36

### Komga administration

Administrators can now:

- Add new EPUB/PDF/CBZ/CBR files from a phone or PC to an allowed library and series folder.
- Edit volume/series metadata and change covers.
- Delete a volume after confirmation identifying the title and explaining that
  its original server file is removed for every user.

New-file upload requires the optional [Debian companion and reverse proxy](../KOMGA_LIBRARY_MANAGEMENT.md).
Metadata, covers and deletion use native Komga APIs without the companion.
Duplicate filenames are rejected; replacing an existing volume file is not supported.
Upload receipts survive restarts so an uncertain result can be checked before retrying.

The lifecycle was verified on disposable Komga 1.30.1, including nested folders,
metadata, covers, duplicate rejection and deletion. Each server administrator
must configure and validate the companion for their own installation.

### Installation and verification

Build 35 users can update from **Settings → About → App updates**. Earlier builds
can install the current Preview over the existing installation. Do not uninstall
first. Windows users must keep the complete extracted bundle.

The APK keeps the original Android signing identity and includes ARM64, ARMv7
and x86_64. The Windows bundle includes the Kindle worker, notices and corresponding
source. Windows is not Authenticode signed. Release files include `SHA256SUMS.txt`
and the public update manifest.

[Source CI](https://github.com/LeValue/KMReader-Porting/actions/runs/43638043777),
[delivery checks](https://github.com/LeValue/KMReader-Porting/actions/runs/43639902577),
downloaded packages and the public update feed passed verification.
[Detailed evidence and limitations](../VALIDATION.md) include hashes and skip counts.

## Known limits and release status

- Full functional/visual parity and physical-device acceptance are tracked in the
  [porting checklist](../PARITY.md); a green CI run does not complete that work.
- Kindle support is unofficial and currently targets Amazon.it. Personal-document
  editing excludes purchased books. EPUB state migration has
  [documented limits](../KINDLE_LIBRARY_MANAGEMENT.md), including notes/highlights,
  PDFs and editions that cannot be mapped safely.
- Local RAR/CBR reading is not implemented. CBR upload to Komga is a separate feature.
- AI/model-management and translation extensions remain future work.
